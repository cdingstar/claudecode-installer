## #001 启动即崩：PropertyNotFound「在此对象上找不到属性 Root」

- **发现方式**：Windows 真机验证（0825 版，来自微信直接运行的反馈）
- **现象**：双击 bat 后立即报 `在此对象上找不到属性"Root"`，位置 `main.ps1:21`，退出码 1，logs 目录为空
- **根因**：main.ps1 第 21 行 `$Script:InstallState.Root = $AppRoot` 写在**模块加载之前**，而 `InstallState` 要等第 29 行加载 runner.ps1 时才定义。在 `$null` 上设置属性即报 PropertyNotFound；又因该行在 try 保护外 + `$ErrorActionPreference='Stop'`，脚本裸崩，连日志都没初始化
- **修复**（三层）：
  1. 删除该行（`InstallState.Root` 全项目零消费者）
  2. 模块加载段全部纳入 try/catch：文件缺失或加载失败立即给出中文定位（E-SYS-004），不再裸崩
  3. 新增 `Start-PreflightCheck` 启动自检：全部模块加载后校验 26 个关键函数 + 4 个状态变量就位，任何缺失以 E-SYS-004 暴露
- **防复发**：新增 `-CheckOnly` 干跑模式，走完整启动链（param → 自举 → 14 个模块加载 → 自检）但不执行安装——**开发机上就能验证启动路径**，正是此前测试的盲区
- **已验证**：CheckOnly 在开发机通过；破坏性测试三种场景（删模块文件 / 模块语法损坏 / 变量静默缺失）全部被正确拦截并输出中文提示

## #002 配置写入崩溃：$Home 是 PowerShell 只读保留变量

- **发现方式**：开发期模拟测试
- **现象**：`Write-OnboardingFlag` 参数命名 `$Home`，赋值即抛 `Cannot overwrite variable Home`，导致 `.claude.json` 与 CLAUDE.md 写入失败
- **修复**：参数改名 `$HomeDir`
- **教训**：PS 参数命名避开保留自动变量（$Home/$Host/$PID/$Args/$Input 等）

## #003 1M 上下文窗口配置永不生效：-like 的字符集陷阱

- **发现方式**：开发期模拟测试
- **现象**：`$model -like '*[1m]'` 中 `[1m]` 被 -like 解释为「单字符 ∈ {1, m}」的通配符字符集，永远匹配失败，`CLAUDE_CODE_AUTO_COMPACT_WINDOW` 从不写入
- **修复**：改用 `$model.Contains('[1m]')`
- **教训**：含 `[` 的字面量做模式匹配，禁用 -like / -match 裸写，用字符串方法或转义

## #004 自检报告显示 True/False 而非版本号：-or 陷阱

- **发现方式**：代码复查
- **现象**：`(A) -or (B)` 返回布尔而非先成功的值，报告里组件版本列显示 True/False
- **修复**：新增 `Get-FirstVersion` 顺序探测函数

## #005 版本探测误报「未安装」：EAP=Stop + stderr 重定向

- **发现方式**：代码复查（PS5.1 经典坑）
- **现象**：`$ErrorActionPreference='Stop'` 下 native 命令（node.exe 等）向 stderr 写任何内容都会触发异常，即使 try/catch 也导致返回 $null → 已装组件被误判未装 → 重复安装
- **修复**：`Get-CommandVersion` 内部临时把 EAP 降为 Continue，finally 恢复

## #006 方案输出污染返回值

- **发现方式**：容错内核单元测试
- **现象**：方案 Action 内的 `Write-Output` 会混入 `Invoke-InstallStep` 的布尔返回值，main.ps1 的 `$nodeOk` 等判断收到数组
- **修复**：runner 中 `& $plan.Action | Out-Null`

## #007 分发包中文文件名乱码：macOS zip 不设 UTF-8 标志

- **发现方式**：打包校验
- **现象**：macOS `zip` 命令存储中文文件名但不设置 EFS（UTF-8）标志位，Windows 解压时按 GBK 解释 →「双击安装ClaudeCode.bat」变乱码
- **修复**：改用 Python zipfile 打包（自动设 EFS）；bat 行尾统一 CRLF；打包后逐文件 SHA256 比对

## #008 改进：API 测试连接错误全面中文化（原始错误 ID + 中英双语）

- **背景**：真机反馈 DeepSeek 402（余额不足）当时只显示干巴巴的「HTTP 402」；用户要求错误查询出来变中文，并保留原始错误 ID + 中英文提示
- **实现**（config-dialog.ps1 的 `Get-FriendlyApiError`，五级匹配）：
  1. **GLM 官方业务错误码表**（26 项，来源 docs.bigmodel.cn/cn/faq/api-code）：读响应体 `error.code`，如 `[HTTP 400 · GLM 1211] 模型不存在`；含 1309（Coding Plan 到期）、1113（欠费）、1311（套餐未含模型）等高频项
  2. **服务端英文消息词典**（DeepSeek 官方口径，来源 api-docs.deepseek.com）：Insufficient Balance → 余额不足 等 17 项
  3. **HTTP 状态码表**：400~504 全量中英对照，格式 `[HTTP 402 · Payment Required] 中文`
  4. **网络层分类**：`[网络]` 前缀 + 超时/DNS/连接/SSL 四类（WebException.Status + 关键词双路径）
  5. 原始消息兜底
- **展示格式**：`[错误 ID] 中文提示（English）（原文：服务端消息）`——英文原文保留便于报障
- **兼容性**：响应体提取兼容 PS5.1（GetResponseStream）与 PS7（ErrorDetails）
- **已实测**：DeepSeek 401/402/400 真实场景、GLM 假 Key、网络异常场景；GLM 数字码路径以单元测试验证
- **已知边界**：GLM 的 Anthropic 兼容端点部分错误不返回数字 code（仅 type/message），此时走词典/状态码兜底——行为正确；macOS 开发机 DNS 被通配劫持，DNS 失败场景只能在 Windows 真机验证

## #009 旧版 Node 16 被误判「已安装」+ claude 预检只查存在不验运行

- **发现方式**：Windows 真机验证（第二台机器，预装 Node v16.17.0）
- **现象**：
  1. Node v16.17.0 被「跳过（已安装）」，但 Claude Code 2.x 硬性要求 Node ≥ 18
  2. `[Claude Code] 跳过（已安装）` 与自检 `[失败] Claude Code 不可用` 自相矛盾——机器上有旧残留的 claude.cmd，PATH 探测只验证「命令存在」没实测 `--version`
- **根因**：两个幂等预检都缺关键校验——`Test-NodeReady` 不查版本下限；`Test-ClaudeReady` 的 PATH 分支不实测运行
- **修复**（四处）：
  1. `Test-NodeReady`：新增 `Test-NodeVersionAtLeast`（主版本 ≥ 18 才算已装），旧版 Node 会触发安装 v22（zip 装到用户目录，不动系统里的旧版）
  2. `Test-ClaudeReady`：PATH 分支改为 `Get-Command` 取实际路径后实测 `--version`，跑不起来的残留 shim 不再算已装 → 触发 npm 覆盖升级
  3. `Add-UserPath` 改为**前插**（去重后插到 User PATH 最前）：本安装器的 Node 目录优先于系统旧版，缓解 PATH 遮蔽
  4. `Invoke-InstallStep`/安装报告：失败步骤记录并输出「最后错误详情」（方案名+错误 ID+原始信息），不再只有光秃秃的错误 ID——远程定位不再必须拿到 logs
- **附带改进**：step5 报告新增「特别注意」——实测 PATH 里 node 主版本 < 18 时，提示用户卸载旧版 Node 或手动调整环境变量顺序
- **预防**：幂等预检的验收标准从「命令能找到」升级为「命令能运行且版本达标」；已纳入代码注释（Test-NodeReady / Test-ClaudeReady 头部）

## #010 改进：安装报告细节增强 + 版本号管理（v1.1 起）

- **背景**：真机验证两轮后，用户要求报告增加更多 log 细节（安装路径、情况、结果），每项输出可定位错误的详细信息；并确立版本规则
- **版本规则**：**每次重新打包，小版本号 +1**（如 1.1 → 1.2），包名 `ClaudeCode安装器-vX.Y-MMDD.zip`；版本号在 main.ps1 的 `$Script:InstallerVersion` 维护，横幅与报告均显示
- **报告新增/增强板块**：
  1. 【环境信息】：系统版本/64 位/用户名/安装器目录/开始时间/总耗时/本次日志文件名
  2. 【组件状态】：成功项附「实际调用路径」，失败项附「期望安装路径 + 文件存在性」（文件存在但无法运行 ≠ 文件不存在，二者指向不同问题）
  3. 【安装明细】：每步附耗时（秒）；失败详情含「尝试镜像数、总重试次数、最后 HTTP 状态」（E-DL-001 的 Detail 已增强）
  4. 【下载明细】：每个文件的来源（在线镜像 URL/缓存复用/离线包）、大小、耗时、重试次数——下载类问题不再必须回传 logs
  5. 【PATH 检查】：User 级 PATH 全量顺序 + 存在性 + 组件归属标注 + 终端实际解析到的 node 路径与版本（可发现旧版遮蔽）
- **健壮性加固**：报告是最后防线，所有路径拼接改为空值安全的字符串拼接（`Get-SafeDir` + try/catch），目录函数异常不再导致报告崩溃
- **回归**：端到端模拟（成功/跳过/失败混合场景）报告全板块正常；语法+BOM+启动链全过

## #011 claude.exe 损坏报「与 64 位 Windows 不兼容」+ npm 重装被跳过

- **发现方式**：Windows 真机（wxb 机器）手动 `cmd → claude` 报错：
  「由于与 64 位版本的 Windows 不兼容，此程序或功能 …bin\claude.exe 无法启动或运行」
- **根因**（用户判断正确，与 Node 16 无关）：
  1. 该报错是 Windows 对**无法解析的 PE 文件**的兜底提示（64 位系统无 16 位子系统，损坏的 exe 被误判为 16 位程序）→ claude.exe 文件本身损坏（下载不完整/被杀毒软件篡改截断）
  2. 叠加缺陷：`npm install -g` 看到包目录已存在且版本相同会报 "up to date" **跳过替换**——即使 v1.1 的预检已能识别损坏并触发"重装"，npm 也不会覆盖损坏文件，形成死循环
- **修复**（v1.2）：
  1. 新增 `Clear-BrokenClaudeInstall`：npm 安装前检测旧包（bin\claude.exe 缺失或实测 `--version` 失败即判损坏）→ 整包删除（含 win32-x64 平台包与三个 shim）→ 强制 npm 全新下载
  2. `E-CC-002` 错误文案补充「与 64 位 Windows 不兼容」的定向指引（杀毒软件白名单）
- **已测**：三场景单元测试（损坏→清理 / 完好→保留 / 缺失→清理）全部通过
- **预防**：所有「已存在但要升级/修复」的路径，必须考虑包管理器的"已是最新"跳过分支——清理或 --force 二选一

## #012 Python 全方案「无效的 URI」下载失败 + Python 已装判断不全 + claude 失败无杀软诊断

- **发现方式**：Windows 真机 v1.2 报告（信息增强后首战建功）
- **根因一（核心）——PowerShell 数组内裸 `-f` 的解析陷阱**：
  ```powershell
  @("...{0}..." -f $v, "...{0}..." -f $v)   # 错：-f 右操作数吞掉逗号，实为 1 个元素！
  @(("...{0}..." -f $v), ("...{0}..." -f $v))  # 对：每元素加括号
  ```
  连锁：`Get-PythonUrls` 返回单字符串 → `$urls[0]`/`$urls[1]` 取到字符 `'h'`/`'t'` → `HttpWebRequest::Create('h')` → 「无效的 URI: 未能确定 URI 的格式」→ 2"镜像"×3 次 = 6 次全败。**与网络无关**（同一台机器 Node zip 从华为云 4 秒拉了 34MB）。step2 的 Git 镜像数组有完全相同的写法，只因一直「已装跳过」未爆发
- **根因二——Python 已装判断不全**：机器 PATH 里只有 `Python\Launcher`（py.exe），预检没查 `py` 启动器也没扫 `Python3*` 安装目录，导致误判未装
- **根因三——claude 失败缺定位信息**：E-CC-002 只说「无法执行」，无杀软检测、无 exe 体检
- **修复**（v1.3）：
  1. step3 `Get-PythonUrls`、step2 `$Script:GitPortableUrls` 全部元素加括号
  2. 下载器入口防御：过滤非法 URL 并日志留痕，全无效直接报 `E-DL-004`（Fatal，明确指向安装器缺陷而非用户环境）
  3. `Test-PythonReady` 四路探测：`python` 命令 / `py -3` 启动器 / `Python3*` 目录扫描 / 自装位置
  4. 新增 `Get-ClaudeFailureDiagnosis`：claude 运行失败时体检（exe 是否消失、平台包体积是否异常偏小=被截断的「16 位不兼容」典型原因、**杀毒软件名单** + 白名单指引），诊断全文进错误详情与报告
  5. runner 收集**所有**失败方案的错误（此前只留最后一个，npm 方案的 stderr 被丢弃）
- **已测**：URL 数量/格式 ✓；非法 URL 报 E-DL-004 ✓；华为云 Python HEAD 200 ✓；诊断函数输出 ✓
- **预防**：数组内任何含 `-f`/`-join`/`-split` 的表达式一律加括号；下载器永远先验 URL 格式再连接

## #013 「16 位不兼容」真凶 = 500 字节占位 stub；npm 失败真凶 = cmd 引号剥离

- **发现方式**：Windows 真机 v1.3 报告（GBK 乱码错误 + exe 体检数据）
- **根因一（claude「16 位不兼容」，实锤）**：claude-code 2.1.x 的 npm 包结构——
  主包 `bin\claude.exe` 是 **500 字节占位 stub**，真实主程序在平台包
  `@anthropic-ai/claude-code-win32-x64\claude.exe`（**384MB**）；npm 正常安装靠
  `postinstall: node install.cjs` 把真身复制覆盖 stub。
  本安装器的 tgz 手动方案漏了这步 → 500 字节伪 PE → Windows 报「与 64 位 Windows 不兼容」。
  真机上旧安装的残留 stub 同理（旧 postinstall 未跑成）。**与杀毒软件无关（此前误判）**
- **根因二（npm 方案全败，乱码解码后实锤）**：报错原文
  `'C:\...\npm.cmd" "config" "set"...不是内部或外部命令`——`cmd /c` 的老式引号剥离：
  Start-Process 把含空格参数转手加引号后，cmd 把整串当成了命令名
- **修复**（v1.4）：
  1. `Invoke-NpmWait` 重写为 PS 原生 `& npm.cmd @args` 调用（零引号转换），输出尾部 6 行入错误详情
  2. tgz 方案补上关键步骤：校验平台包 exe ≥ 50MB 后 `Copy-Item` 覆盖 stub（真实 384MB 复制实测通过）
  3. `Clear-BrokenClaudeInstall` 判据升级：`bin\claude.exe < 1MB` 直接判损坏（stub 未替换），清理重装
  4. 诊断提示同步更正（此前误导性地指向杀毒软件）
- **已测**：真实 tgz 解压→stub(500B)→复制→真身(384MB) 链路 ✓；npm & 调用 ✓；stub 判损清理 ✓
- **预防**：凡跨进程调用 .cmd/.bat，一律优先 PS 原生 `&`（或 .NET ProcessStartInfo 手工拼 Arguments），不经 Start-Process+cmd 二道贩子；对「占位文件 + postinstall 补全」型包结构，手动安装必须复刻 postinstall 语义

## #015 改进：VS Code 镜像策略调整——微软官方中国通道为主，华为云降为备份（v1.6）

- **背景**：用户质疑「为什么走华为云」，要求调研其他方案、华为云仅作备份
- **调研结论**（全部实测）：
  | 候选源 | 结果 |
  |---|---|
  | 微软官方中国下载通道 `vscode.download.prss.microsoft.com/dbazure/...` | ✅ HTTP 200（231MB），官方 CDN、国内直连 |
  | 微软官方更新 API `update.code.visualstudio.com/api/update/...` | ✅ 可用，返回最新版本/commit/SHA256/直链（仅 KB 级元数据） |
  | `vscode.cdn.azure.cn` | ❌ 当前网络不可达（未采用） |
  | 阿里云 / 腾讯 / npmmirror / 清华 / 中科大 | ❌ 均无 VSCode 镜像 |
  | 华为云 `/VSCode/<版本>/` | ✅ 可用但**同步滞后 29 个版本**（1.105.0 vs 官方 1.134.0）→ 降级为备份 |
- **新方案链**：
  A 主：官方 API 动态取最新版元数据（版本+commit+SHA256）→ 官方中国通道直链下载（**含 SHA256 校验**）→ 静默安装；
