# Release Notes（发布说明）

> **版本规则**（v1.12 起生效）：
> - 每次修改并重新发布，小版本号 +1（如 1.12 → 1.13），统一维护在 `sourcecode/VERSION`
> - 完整版本格式 **`v1.x(yyyymmdd)`**，日期为打包当日，由 `sourcecode/build.sh` 打包时自动生成
> - 版本号出现在三处：**zip 包名**、包内 **VERSION 文件**、**程序启动横幅**（安装报告与反馈邮件主题同步显示）
> - 每次发布必须在本文件登记：版本、日期、平台、修改内容
> - Windows 与 Mac 使用**同一版本号**（v1.12 之前双端独立编号：Windows 主序列 v1.1→v1.11，Mac 序列 v1.0→v1.5；统一后 Mac 并入主序列）
>
> **发布流程**：改代码 → `sourcecode/VERSION` 小版本 +1 → `zsh sourcecode/build.sh` → 产物在 `Dist/Windows|Mac/` → 本文件登记条目

## v1.13(20260917)

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-17 |
| 平台 | Windows + Mac |
| 类型 | 行为调整 |

**修改内容**：

1. **已有有效配置不再静默跳过（#026，双端一致）**：
   - 原行为（#017）：重跑安装器时，已保存的 API Key 实测可用 → 整个配置步骤静默跳过，用户无感知
   - 新行为：实测可用时**弹出提示**「已存在有效的 API Key 配置」（含接口地址与模型名），用户二选一：
     - **保留现有**（默认按钮/直接回车）→ 跳过配置步骤，报告记「跳过（已有配置验证通过，用户选择保留）」
     - **重新配置** → 打开完整配置窗口，可更换供应商 / API Key / 模型
   - Windows：新增 `Confirm-KeepExistingConfig`（config-dialog.ps1，MessageBox 是/否 + 控制台问答降级链）
   - Mac：step5_config 验证通过后弹 osascript 二选一（「重新配置」/「保留现有」，Esc 取消=安全默认保留）
   - 不受影响的原有行为：Key 实测失效仍直接弹配置窗口重输；「重新配置APIKEY.bat/.command」单独调起仍强制弹窗（#023）
2. 双端内置兜底版本号同步 1.12 → 1.13

## v1.12(20260917)

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-17 |
| 平台 | Windows + Mac（版本号自本版起双端统一） |
| 类型 | 工程整理 |

**修改内容**：

1. **项目目录重组**（按用途四分）：
   - `docs/` —— 需求与说明文档（使用说明、使用说明-Mac、问题备案、ReleaseNotes）
   - `sourcecode/Windows|Mac/` —— 双平台源代码（含打包脚本 build.sh、版本文件 VERSION）
   - `Dist/Windows|Mac/` —— 最终分发 zip（发给用户的文件，按平台分目录）
   - `archive/` —— 历史运行产物归档（日志、安装报告、反馈包，不随发布）
2. **统一版本号机制 `v1.x(yyyymmdd)`**：单一来源 `sourcecode/VERSION`（纯数字）；`build.sh` 打包时组合当日日期生成完整版本串，写入 zip 包名与包内 VERSION 文件；Windows（main.ps1）与 Mac（installer-mac.sh / uninstall-mac.sh）启动时读取显示于横幅、安装报告、反馈邮件主题
3. **新增统一打包脚本 `sourcecode/build.sh`**：支持 `win` / `mac` / `all`；Python zipfile 打包（自动置 EFS/UTF-8 标志位，Windows 解压中文名不乱码，见问题备案 #007）；自动排除开发工具与运行产物；打包后三重校验（EFS 标志 / bat CRLF / 逐文件 SHA256）；包内自动附带对应平台使用说明
4. 修复 `重新配置APIKEY.bat` 行尾为 LF → 统一 CRLF（#007 规则）
5. 文档同步更新：使用说明×2 的目录结构与版本说明、问题备案防回归清单路径
